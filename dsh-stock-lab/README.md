# DSH Stock Lab

> **侧栏显示名：看盘助手** ｜ 插件标识 `dsh-stock-lab`（内部标识保持不变：改它会波及路由、localStorage 键与数据目录）
> A 股看盘与研究插件 · DeepSeek Harness
> **不构成投资建议**，仅供研究与学习。

## 定位

不是行情软件的复制品。传统软件回答"市场发生了什么"，Stock Lab 还要回答：

- 为什么发生？
- 这个现象相对市场/行业是否异常？
- 有哪些可能解释？哪些有数据支持？
- 能否转化成可验证的研究假设？
- 未来能否自动跟踪并复盘？

## 架构铁律（已被测试强制）

1. **UI 与 LLM 都不得直接访问行情 API** —— 全部经 MarketService
2. **只有 `src/services/market-service/` 可以 import `src/datasource/`** —— 测试自动校验，违规即失败
3. **LLM 不算关键金融数据** —— 收益/波动/z-score/超额收益全部由代码计算
4. **数据必须带来源与时间戳** —— 每个响应都有 `source` 与 `fetchedAt`
5. **不把相关性说成因果** —— 写进 skill 与工具描述

## Watch Engine（智能盯盘）

盯盘不是「价格到某值提醒」。支持 **9 种智能条件**：

| kind | 含义 | params |
|---|---|---|
| `price_threshold` | 价格阈值 | `{op, value}` |
| `daily_change_pct` | 当日涨跌幅 | `{op, value}` |
| `volume_anomaly` | 成交量异常 | `{n:20, mult:2}` |
| `turnover_spike` | 换手率骤升 | `{value}` |
| `volatility_breakout` | 波动率突破 | `{n:20, ratio:1.6}` |
| `relative_strength_shift` | 相对强弱突变 | `{n:20, threshold:5, direction, benchmark}` |
| `money_flow_anomaly` | 资金流异常 | `{days:5, threshold(元), direction}` |
| `sector_relative` | 个股与行业背离 | `{threshold, direction}` |
| `hypothesis_review_due` | **研究假设到复盘日** | 必须传 `noteId` |

### 与研究笔记的联动

`hypothesis_review_due` 把 Watch Engine 和 Research Notebook 接起来：规则关联一条笔记，到复盘日时触发提醒，**并把当时的预测原文带进提醒**，引导用户对照实际走势判断假设成立/部分成立/被推翻。

这正是项目目标里的「建立 Watch 条件 → 未来自动复盘」这一环。

### 冷却与周期

- **冷却**：同一规则在 `cooldownMinutes`（默认 240）内不重复写触发记录，避免盘中的持续状态把提醒刷屏；被抑制时结果里会注明 `suppressedByCooldown`
- **周期评估**：Host 侧每 5 分钟自动评估（`DSH_STOCK_LAB_WATCH_MINUTES` 可调），**只在交易时段运行**（09:30–11:30 / 13:00–15:00，自动跳过周末）；`timer` 服务不可用时降级为仅手动/工具触发并写日志说明
- **判定即证据**：每条判定都返回 `metrics`（触发所依据的具体数值），如 `excess: -13.96`、`ratio: 2.93`

### 实测（真实市场数据）

```
宁德时代 · 20日相对强弱突变 → 触发(critical)
  近 20 日个股 -21.92% vs 基准 -7.96%，超额 -13.96pp（阈值 5pp）

贵州茅台 · 价格 ≥ 1300 → 触发(info)  现价 1335，当日 +1.25%

宁德时代 · 假设到复盘日 → 未触发（复盘日 2026-11-06 未到）
  仍返回提醒文案与预测原文，供到期时使用
```

### 主动提醒：架构边界与正确做法

**插件无法向会话推送消息。** 这是 DSH 的作用域设计（插件上下文到不了 agent 层），不是缺陷——`session.announce` 只是变更信号，没有注入能力。所以「主动提醒」由两层配合：

| 层 | 做什么 |
|---|---|
| **插件侧** | Host 每 5 分钟自动评估（仅交易时段）→ 触发写入记录；`watch_digest` 工具与 `/watch/pending` 路由把「该看什么」聚合成紧凑简报 |
| **会话侧** | 用 DSH 自带的提醒（`schedule_create`）在固定时间把它叫起来 |

`skill.md` 里已写明这个模式，所以当用户说「帮我每天盯着」「收盘后提醒我」时，AI 会：
1. 建立/确认盯盘规则
2. 用 `schedule_create` 建一条提醒（例：交易日 15:30，prompt = 「调用 watch_digest 汇报盯盘情况」）
3. 明确告知提醒已建立及触发时间

`watch_digest` 的输出按严重度分组，**每条都带依据数值**，并把到期的研究假设单列出来要求复盘：

```
### 盯盘触发（未确认 2 条 / 历史累计 2 条）

**重要（1）**
- [critical] 宁德时代 20 日相对强弱走弱｜近 20 日个股 -21.92% vs 基准 -7.96%，
  超额 -13.96pp（阈值 5pp，方向 underperform）

**提示（1）**
- [info] 贵州茅台 价格不低于 1300｜现价 1335，阈值 >= 1300，当日 1.25%
```

## 通达信（TDX）公式引擎

在对话里粘贴公式、或指定公式文件，即可解析并计算。**这是兼容子集，不是完整通达信**——遇到不支持会明确指出，不给"看起来像"的结果。

### 支持的范围

| | 内容 |
|---|---|
| 语句 | `A:=EXPR;`（中间变量）· `A:EXPR;`（输出线）· `A:EXPR,COLORRED,LINETHICK2;`（绘图属性） |
| 容错 | 末行漏分号、整篇按行写不带分号、`{ }` 与 `//` 注释、**中文变量名**、字符串字面量 `'底'`、大小写不敏感 |
| 函数 | `MA EMA SMA REF HHV LLV SUM STD CROSS COUNT EVERY EXIST IF IFF BARSLAST BARSSINCE BARSCOUNT MAX MIN ABS SQRT POW LOG EXP SIGN ROUND INTPART CEILING FLOOR` |
| 序列 | `O H L C V VOL AMOUNT`（**7 个名字 → 6 个序列**：`V` 与 `VOL` 同指成交量）+ 英文全称与别名（`OPEN HIGH LOW CLOSE VOLUME AMO`，共 13 个名字） |

### 明确不支持（会报错，不猜）

**"不能用"的名字分开报（原因不同，出路也不同）**——四类共 37 个名字，处置由代码分支决定（`tdx-evaluate.js:146-182`）：

| 类别 | 数量 | 函数 | 为什么不行 | 出路 |
|---|---|---|---|---|
| **未来函数** | 7 | `ZIG PEAK PEAKBARS TROUGH TROUGHBARS BACKSET REFDATE` | 会随新数据**重画历史**，拿去判断信号会得到虚假高胜率 | 只想看图时用 `run_formula` + `allowFutureFunctions=true` |
| **缺数据** | 7 | `FINANCE FINANCE_EX DYNAINFO CAPITAL SELFDATA HYBLOCK INBLOCK` | ⚠️ **这不是未来函数**——它们不会重画历史。真正限制是引擎只提供 K 线序列，拿不到财务与实时盘口 | 基本面筛选请先用 `stock_financials` / `stock_quote` 取数值再筛；`CAPITAL` 类可用本地库/行情侧数据代替 |
| **未实现** | 5 | `COST WINNER LWINNER PPART PWINNER` | 只靠 K 线理论上可算，属实现缺口 | 待实现 |
| **绘图指令**（会被忽略） | 18 | `DRAWTEXT DRAWICON DRAWNUMBER DRAWLINE DRAWKLINE STICKLINE POLYLINE PARTLINE DRAWBAND DRAWRECTREL VERTLINE HORLINE DRAWGBK`（13 个）+ `_FIX` 变体 5 个（`DRAWTEXT_FIX` / `DRAWICON_FIX` / `DRAWNUMBER_FIX` / `DRAWLINE_FIX` / `DRAWRECTREL_FIX`） | 数值照算，但文字/图标/画线不显示 | 不需要出路：**结果里会列出被忽略了哪些**，不假装画出来了 |

> 上述四类都**不计入**"已实现函数"数量：可计算的只有 **29 个函数 + 7 个序列变量名**（`supportedFunctionNames()` 实返回 29）。
> ⚠️ 注意口径：`O H L C V VOL AMOUNT` 是 **7 个名字、6 个序列**——`V` 与 `VOL` 同指成交量（`tdx-evaluate.js:18-25` 的 `SERIES_VARS` 共 13 个名字，映射到 6 个序列）。说"7 个序列"就是错的。
> 注册表 `FUNCTIONS`（Map）共 58 个键，但那是 **29 个函数 × 2**（大写名 + 小写别名，函数名大小写不敏感）——**不是**"58 个函数"；
> 上表四类"不能用"的名字（共 37 个）**不在**这张表里，各在独立集合。所以"支持 40+"这类数字是把函数、行情序列、以及不能用的名字混着数的结果。

| 项 | 原因 / 出路 |
|---|---|
| 加密公式文件（`.tne` 等二进制） | 格式无法还原。**请在通达信「公式管理器」里复制源码或导出 .txt** |
| 跨公式引用（`"MACD.MA1"`） | 需跨公式解析；请把被引用的公式展开 |
| 口径未确认的平滑函数（`MEMA WMA DMA EXPMA`） | 宁可报"不支持"，也不给一个近似值 |

> 早期版本把 `FINANCE`/`DYNAINFO` 误归为「未来函数」，于是"我们没有财务数据"被说成"你的公式会重画历史"——**指向了错误的原因**。现已按上表分开，并有测试锁住这个区分。

### 未来函数检测（这个必须做）

通达信里 `ZIG / PEAK / PEAKBARS / TROUGH / TROUGHBARS / BACKSET / REFDATE` 这 **7 个**会在新数据到来时**重画历史**。用它们判断买卖信号会得到虚假的高胜率。

> ⚠️ **不要把 `DYNAINFO` / `FINANCE` 归到这一类**：它们不会重画历史，只是引擎拿不到财务/实时盘口数据（属上表"缺数据"）。
> 这两者混为一谈会让用户找错方向——这是本项目真实修过的分类错误，也有测试锁着（见上表下的说明）。

因此：`analyze()` 标出函数名并提示；`run()` **默认拒绝计算**，只有显式允许（`allowFutureFunctions`）才出图。

### 选股信号的安全判定

通达信**选股（条件）公式**的约定是「**最后一条输出线必须是 0/1 条件**」，例如：

```
MA5:=MA(CLOSE,5);
MA20:=MA(CLOSE,20);
放量:=VOL>MA(VOL,20)*1.5;
XG:CROSS(MA5,MA20) AND 放量;
```

本引擎做了严格校验：

- 最后一条输出线**全为 0/1/null** → 视为选股条件，返回命中次数、命中日与命中率
- 否则（如 `MA5:MA(C,5);`）→ **明确拒绝**并说明原因，避免把每条均线值都算成"命中"

**当前范围：只支持技术面选股**（基于 K 线序列）。含 `FINANCE`/`CAPITAL`/`DYNAINFO` 的基本面选股公式**无法运行**，会明确告知原因与替代路径。

> 批量选股（跨全市场跑一个条件公式）尚未实现，见 ROADMAP T5.7。

### 主页面展示

导入的公式可**叠加到 K 线上**：

| 判定 | 去处 | 例子 |
|---|---|---|
| 数值落在价格区间内（留 10% 余量） | **主图叠加** | `MA5 / MA20 / BBI` |
| 量纲不同 | **副图**（含零轴） | `MACD`（有负值）/ `RSI`（0~100） |
| 通达信 `COLORSTICK` 等柱状属性 | 副图**直方图** | MACD 柱 |
| **纯 0/1 条件线** | **不画曲线**，在命中的 K 线上标 **▲** | `XG:CROSS(...)` |

几个刻意的选择：

- **价格轴会把主图叠加线一起纳入范围**——否则均线在价格区间外时会被裁掉
- **0/1 条件线不画成曲线**：一条在 0~1 之间跳动的线糊在图的角落里没有意义；改成在命中的柱上标 ▲，并在图例里给命中次数
- **线色只用 DSH 主题 token**：切换明暗主题自动跟随。通达信的 `COLORRED/COLORGREEN/COLORYELLOW` 等属性如实映射到主题色，但主题可用颜色有限，因此部分同义色会落到同一 token（这是如实映射，不是色相精确还原）
- **折线在 `null` 处断开**，不跨数据缺口连线
- **公式在「图表当前显示的那批 K 线」上求值**：周期/复权/根数都跟随图表，否则切到周线时刻线与柱体就会错位

### 「指标公式」tab

- 公式列表：名字 / 归属标的 / 输出线 / 解析状态 / 未来函数与绘图指令告警
- **界面内粘贴导入**：填名字 + 粘源码 → 解析 → 成功则自动叠加

## 右栏 Chat（自建对话 + 按标的的线程）

**为什么不复用 DSH 官方会话**（原设计如此，但技术上走不通）：

| 事实 | 来源 |
|---|---|
| `main` 是 keyed slot，**只有保留键 `conversation` 绑定 Session**，我们的 `stock-lab` 键拿不到 Session | `Slots.listSubTree` catalog |
| 客户端插件之间不共享 JS 模块（bundle 只能 `require('react')`），无法 import 官方 Chat 组件 | `dsh-astock` 的 bundle 结构 |
| 强占 `conversation` 键会**替换掉官方会话**（`replaceRisk: shadows-shipped-ui`），等于重写一遍 | 同上 |

**但插件可以自己调 LLM**：`ctx.llm.stream()` 支持 `tools` 与 `tool-call-delta`，
用 `agentDefaultModel` 当前选型，**不需要 API Key**。于是自建，而且有个官方会话没有的好处：
**30 个工具就在本进程内，可以直接调 `execute`**，不必经过 agent 层。

### 三条刻意的设计约束

1. **工具白名单，不是"所有可见工具"**
   `ctx.tools.schemas()` 会把 agent 自有的 `read`/`write`/`bash` 一并带出去——
   那些绝不该出现在一个聊天面板里。因此 Chat 只暴露本插件自己的工具。

2. **数字只能来自工具**
   此前插件代码**零 LLM 调用**；自建 Chat 是第一次引入，所以把约束写进系统提示词：
   不得凭记忆报数、不得心算收益率/波动率/t 值、不得改写工具返回的统计量、不替用户下结论。
   实测模型确实照做——回答里自动带上了数据来源、时间戳与免责声明。

3. **对话保存过程，笔记保存结论**
   原始消息全存（用户要能回看"上个月到底怎么想的"），但**喂给模型多少是另一件事**。
   结论落到 Research Note，而不是靠模型回忆聊天记录。

### 流式与工具循环

```
POST /chat/send          → { runId }（立即返回，后台执行）
GET  /chat/stream?runId= → SSE：round · text-delta · round-done · tool-start · tool-end · done · error
POST /chat/cancel        → 取消进行中的 run
GET  /chat/ask           → 一次性跑完（非流式，便于脚本/无 SSE 场合）
GET  /chat/threads · /chat/messages · POST /chat/delete-thread
```

工具循环的实测行为：

| 场景 | 处理 |
|---|---|
| 参数是半截 JSON（流式分片） | 按 `index` 拼接；缺 id/name 的半成品丢弃 |
| 参数非法（模型写坏了 JSON） | **如实回灌**让它自己修，不猜 |
| 工具抛错 | 变成错误结果回灌，**对话不中断** |
| 连续 6 轮都在调工具 | 停止并给出可执行建议（缩小范围 / 直接讲结果） |
| 模型 `error` / `aborted` 结束 | 报告原因，已产出的文本仍保留 |
| 工具结果过长 | **给模型的截断到 6000 字符，存档保留完整内容**并标注 `truncatedForModel` |

> 一个容易忽略的细节：**工具结果在发生的当下就落库**，不是等整轮结束后补写。
> 否则回看顺序会变成「答案 → 它用过的工具」，读起来是错的。

### 实测（真实 LLM，模型 `magpie/codearts/deepseek-v4.1-flash`）

```
问：贵州茅台现在多少钱？只回答现价和涨跌幅。
  [tool]      stock_quote {"symbols":["600519"]}
  [assistant] 贵州茅台（SH600519）：现价 1335.00 元，涨跌幅 +1.25%
              数据来源：腾讯行情，时间戳 2026-10-23 16:14:58（+08:00）
              ⚠️ 以上为公开信息整理，仅供研究参考，不构成投资建议。

问：刚才你查到的那只股票，它的代码是什么？
  [assistant] 代码是 600519（SH600519）。     ← 没有再调工具，直接从历史答出
```

消息形状按 **DSH 类型声明**（`role:'tool'` + 顶层 `toolCallId`）**被 provider 接受**，
不必退回 `dsh-astock` 的 `role:'user'` + `tool-result` 块写法（两条路都做成可替换）。

### 跨重启的会话匹配（"两周后打开还能接上吗"）

**能。** 这是被专门测试钉住的行为（`tests/chat-persistence.test.mjs`，16 项）：

| 场景 | 行为 |
|---|---|
| DSH 重启 / 插件重装 | 线程存在 SQLite（`~/.dsh/stock-lab/chat/index.db`），**重开后按标的匹配到同一线程**，对话完整保留 |
| `600519` / `SH600519` / `sh600519` / `600519.SH` / `600519.SS` | 全部解析到**同一线程**（避免"两次打开"分裂成两个对话） |
| 深市 / 指数 | 同理：`300750`↔`sz300750`↔`300750.SZ`；`IDX000300`↔`000300` |
| 没聊过的标的 | `thread=null`、消息为空，**不创建**（懒创建，见架构 D15） |
| 全局研究主线 | 独立线程，不与个股串台 |

> ⚠️ **标的规范化（`normalize`）是持久化格式**：线程按规范形式（`SH600519`）索引。
> 若以后改变规范化规则，**旧对话会失联**。因此有测试把当前输出逐条钉死，
> 改动会立刻报警——这是把"改名"当作数据迁移对待，而不是当重构。

二层的真实会话同理：会话 id 由标的**确定性推导**（`sessionIdForSymbol`，
`SH600519` → `session-stocklab-sh600519`），两周后可用 `agentLoop.resume` 找回，
不需要额外的映射表。反推函数 `symbolFromSessionId` 支持"这个会话是哪个标的的"。

### 右栏界面（T6.3 已完成）

右栏是**当前标的会话的视图**——不是一个新的对话列表，而是"这份对话"在面板里的呈现。

| 区域 | 内容 |
|---|---|
| 顶部 | 标题 + 当前宽度 + 收起按钮 |
| 中间（可滚动） | 对话记录：**用户消息成气泡、贴齐面板左边缘、不标角色**；助手回答按 markdown 渲染并带低调标签；**工具调用折成回答下方一行摘要**（默认收起）；流式输出带光标 |
| 空状态 | "还没有关于 SH600519 的对话"+ **4 个可点击的示例问题** |
| 状态行 | 驱动模型与可用工具数；或"正在调用工具…"/"正在回答…"；或错误 |
| 输入框 | 右下角**内嵌**圆形发送按钮（向上箭头，与原生一致）；无内容时置灰；回答中同一位置变成方块「停止」；Enter 发送、Shift+Enter 换行（兼容中文输入法 `isComposing`，不会误发送） |
| 输入框高度 | **拖上边缘调高**（边缘跟手：往上拖变高）；也可用上下方向键 / Home / End / 回车复位；双击复位；高度跨会话记住 |
| 底部常驻 | 免责声明 |

> ⚠️ **按钮禁用态必须同时改文字色**（真实修过的缺陷）：浅色主题下
> `--dsw-alias-button-primary-dimmed` 是**浅灰**，而 `--dsw-alias-label-primary-foreground`
> 是**白色**——只换背景就会得到「白箭头画在浅灰圆上」，几乎看不见。
> 所以禁用规则里同时设置 `color`，并给了一个 token→token 的兜底（不能回退到继承来的白色）。
> 有测试锁住这一点。
>
> **停止态不另换配色**：曾用 `state-warn` 做背景，但它与前景色的对比无法保证；
> 原生也是「同一个按钮换图标」，所以统一配色更稳、也更像原生。

> **不用原生 `textarea` 的 resize 手柄**：那个手柄长在**右下角**，是个小三角箭头，
> 既别扭又与"拖上边缘上下移动"这种直接操作不一致。所以关掉它，改成上边缘的拖拽条。
> 界面上**没有「清空记录」按钮**——要删对话在工作区里删即可（宿主侧接口保留，供脚本/测试用）。

**助手回答按 markdown 渲染**（模型本来就是 markdown 输出的，直接显示源码很难读）：
标题、粗体/斜体、行内代码、围栏代码块、无序/有序列表、引用、表格、分隔线、链接。

实现上有两条硬约束：

1. **不使用 `dangerouslySetInnerHTML`**。模型输出属于**不可信内容**，拼 HTML 会引入注入风险。
   因此是把 markdown 解析成 **React 元素**（`renderMarkdown`），本身就不存在注入面——
   `<img onerror=...>` 这样的输入只会作为**文本**显示。有测试断言"不该出现 img 元素"。
2. **认不出来的行原样输出，绝不吞内容**。宁可少渲染，不可丢字。
   链接也只允许 `http/https`；其它协议（如 `javascript:`）原样显示而不生成可点击链接。

> 用户消息**不做** markdown 渲染——用户打的是普通文字，把它当 markdown 解析会误伤
> （例如下划线、星号会被当成格式标记）。原生也是这个分别。

### 与原生观感一致（做法不是"凭感觉模仿"）

右侧面板刻意使用**主题包真正在用的那套视觉词汇**，而不是自己编数值，所以字号/行高会随
DSH 的字体设置一起变，配色跟随明暗主题：

| 用途 | 变量 |
|---|---|
| 助手消息排版 | `--dsw-font-markdown-base`（与原生 markdown 渲染同一套） |
| 用户消息气泡 | `--dsw-specific-bubble` + `--dsw-radius-lg` |
| 输入框 | `--dsw-specific-input-major` + `--dsw-focus-ring-*` |
| 右栏底色 | `--dsw-specific-sidebar-fill`（与原生侧栏同一底色） |
| 工具返回 | `--dsw-alias-markdown-code-block` + `--dsw-font-markdown-code-block` |
| 小字/说明 | `--dsw-font-xxxs-11` / `--dsw-font-xxs-12` |

**两条必须遵守的规则**（有测试锁住）：

1. **颜色只用 token、不写兜底**——硬编码色值被测试禁止，且必须跟随主题。
2. **非颜色一律写 `var(--token, 兜底值)`**——官方只承诺 14 个 token，这套词汇
   是主题包的内部实现；哪天改名，样式**退化为兜底值**而不是整块静默失效。

> ⚠️ **不要引用 `--sys-*` 之类的变量**：它们只定义在 inspector 的 devtools 样式表里，
> **插件页面中并不存在**，裸引用会让样式静默失效。这是实测确认的（主前端 CSS 对
> `--sys-*` 的引用数为 0）。

**宽度提示只在调整时出现**：拖动或键盘微调时在右上角显示 `380px`，**停手 3 秒后淡出**。
常驻一个灰色数字平时毫无用处，只会持续分散注意力。

几个刻意的行为：

- **不说话就不建会话**（懒创建）。切标的只是读取；没聊过就是空状态。
- **切标的不会打断正在进行的回答**：那段回答属于上一个标的，服务端照样落库——
  界面会如实提示"「SH600036」的回答仍在后台进行，切回去可看到结果"，而不是把它丢掉。
- **停止真的停得住**：实测取消会被 provider 尊重（`模型调用被中断`），
  且已经产生的对话过程**不会丢**（仍完整落库）。
- **完成时先载入权威内容、再清掉流式临时文本**。顺序反了会有一瞬间"答案消失"，
  看起来像把回答弄丢了。

### ⚠️ 按 token 名字挑颜色是不够的（附实际色值）

下面是**从主题包解析出的实际色值**（浅色主题）。两次"发送按钮不清晰"都是因为
**只凭 token 名字猜、没查实际值**：

| token | 浅色主题实际值 | 判断 |
|---|---|---|
| **`--dsw-alias-button-info-fill`** | **`#4176e6`**（DeepSeek 蓝） | ✅ **发送按钮就该用这个** |
| `--dsw-alias-button-info-hover` | `#7aaaff` | 蓝色按钮悬停 |
| **`--dsw-alias-button-primary-fill`** | **`#0f1115`（近黑）** | ⚠️ 名字叫 primary，但它是**单色品牌色**，**不是**那个蓝——发送按钮用它就是错的 |
| `--dsw-alias-label-primary-foreground` | `#fff`（深色主题 `#0f1115`） | 主按钮前景（**蓝底不要用它**，深色主题会变近黑） |
| `--dsw-static-neutral-bluish-00` | `#fff`（**不随主题变**） | ✅ 蓝底按钮的固定白前景 |
| `--dsw-alias-button-primary-dimmed` | `#ebeef2`（浅灰） | 禁用态填充 |
| `--dsw-alias-label-secondary` | `#61666b` | ✅ 禁用态前景（对 `#ebeef2` 对比度 ≈4.97） |
| `--dsw-alias-label-tertiary` | `#81858c` | 次要文字 |
| **`--dsw-alias-label-dimmed`** | **`#e1e5ee`** | ❌ 名字像"淡化文字"，但**是给浅色背景/遮罩用的**——当文字用等于看不见（对比度 1.10） |
| `--dsw-specific-bubble` | `#edf3fe`（淡蓝） | 用户气泡 |
| `--dsw-specific-input-major` | `#fff` | 输入框 |
| `--dsw-specific-sidebar-fill` | `#f9fafb`（浅灰） | ❌ 曾用来给右栏加底色，会让气泡不够突出，已移除 |
| `--dsw-alias-bg-layer-1` | `#fff` | ✅ 右栏底色（纯白，气泡最突出） |
| `--dsw-static-deepseek-500` | `#4176e6` | 蓝的原始调色板值 |

**两条教训**：

1. **token 名字看不出它适合"文字"还是"背景"**——`label-dimmed` 就是反例。
2. **名字带 "primary" 不代表颜色对**——`button-primary-fill` 是近黑，而原生发送按钮是蓝。
   两次改色失败都是因为按名字猜。**改颜色前先解出实际值、算对比度。**

**工具调用不挡路，但不隐藏**

工具返回是**中间过程**，不是给用户看的内容——直接铺在回答前面就是噪音。
但它也不能完全丢掉：**"数字来自工具调用"是本项目的信任基础**，而且工具失败必须看得见。

所以按"轮次"分组（一条提问 + 其间工具 + 回答），工具折成回答下方的**一行摘要**：

```
🔧 使用了 2 个工具                                    明细
```

- **只报数量，不列举工具名**——点「明细」就能看到是哪些工具（含参数与完整原始返回）。
  列在这一行只是重复信息，还会把这一行撑长。
- **默认收起**，点「明细」才展开（可审计，但不挡路）
- **失败不藏**：那一行会变成 `使用了 2 个工具，其中 1 个失败` 并显示警示色
- 流式过程中也只占一行（`🔧 stock_quote…`），不再逐个铺开
- 中途取消（有工具、没回答）时，工具摘要仍保留——过程不丢

> 取舍说明：这个项目一直强调"每个数字都要能溯源"，所以我没有把工具信息彻底移除，
> 而是**从"铺满屏幕"改成"一行 + 一次点击可达"**。如果连这一行也不想要，可以再简化。

## K 线交互（按看盘软件的习惯）

**目标是替代证券软件**（证券软件的短板正是没有 AI），所以操作按看盘软件来，不用新学一套。

| 操作 | 键位 / 手势 |
|---|---|
| 放大 / 缩小 | **↑ / ↓**（↑ = 更少根、蜡烛更粗）；也可用 `+` / `-` |
| 向左 / 向右平移 | **← / →** |
| 整屏翻页 | PageUp / PageDown（半屏步长） |
| 跳到最早 / 最新 | Home / End |
| 缩放 | **鼠标滚轮**，且**以指针所在那根为锚**（鼠标指着哪里，哪里不动） |

**根数预设（60/120/250/500）已移除**——四个固定档位既不够用（**根本无法往回看历史**），又占地方。

### 实现要点（这三条不做对就会"画得对、显示歪"）

1. **一张缓冲区 + 一个可视窗口**，而不是"想要几根就请求几根"。
   缓冲区长 `BARS_BUFFER = 800`，窗口是 `{ count, end }`（可见根数 + 右边缘下标）。
   缩放/平移只改窗口，**不重新取数、不重算指标**——所以滚轮是即时的。
2. **指标在缓冲区上算、再按窗口切片**。
   若只按可见窗口算，窗口最左边那根的 MA20 会变成空值（它需要之前的 19 根），
   而且每平移一格都要重算一遍。
3. **几何常量共用一份**（`CHART_GEO`）。SVG 用固定 viewBox 再缩放到容器，
   所以指针坐标必须先换算到 viewBox 单位；两处各写一份就会在容器变宽时算偏。

另外：`end < 0` 是哨兵值，表示"**跟随最新**"。只有当用户主动往左平移过之后才记绝对下标——
否则新交易日进来后画面会停在旧位置。切标的/周期/复权时回到最新（看盘软件也是这样）。

### ⚠️ 历史深度：目前约 2~3 年（数据源限制，不是软件问题）

实测（`web.ifzq.gtimg.cn`，与插件同一接口）：

| 请求 | 实际返回 |
|---|---|
| 500 根 | 501 根（2024-09 ~ 2026-10） |
| **800 根** | **801 根（2023-07 ~ 2026-10）← 实际上限** |
| 1500 根 | **641 根**（请求更多反而拿到更少） |
| 3000 根 | `param error`（上游拒绝） |

两个结论：

- **日线上限约 800 根 ≈ 3.2 年**，与证券软件的 10+ 年有差距。这是**上游限制**，
  我们的 800 上限与它恰好一致（不是我们卡住的）。
- **请求超过 ~800 会静默返回更少的数据，而不是报错** —— 这种"静默降级"必须记住，
  所以不要盲目调大 count。

因此缩放到数据起点时，图表会明确显示 **"已到数据起点（共 N 根，最早 YYYY-MM-DD）"**，
而不是默默停住让用户以为是软件卡了。

**要更长的历史，可行的三条路**（待定，尚未实施）：

1. **周线 / 月线**：同样 800 根，周线 ≈15 年、月线更长——长期结构今天就能看。
2. **本地库随时间累积**：本地库不受单次接口上限约束，持续采集就会超过 800 根。
3. **更深的历史数据源**：需要另接（此前被推迟的 pytdx / Tushare 属于这一类）。

## 图表画线（标注）

支持在 K 线图上画线/标注，**并且可以让 AI 来画**——这是"证券软件 + AI"最直接的一处结合：

> 你：「帮我在图上画一条水平线，用最近 60 个交易日的最低价」
> AI：先调 `stock_kline` 取真实数据 → 算出最低价 → 调 `save_drawing` 落到图上，并说明依据

| 类型 | 锚点数 | 用途 |
|---|---|---|
| `hline` | 1 | 水平线（价格位，如颈线/支撑） |
| `trend` | 2 | 趋势线（两点连线） |
| `marker` | 1 | 标记某一天（财报日/事件日） |

### 画法（交互）

工具栏上**常驻**画图工具（用户反馈：没必要收起）：

```
日 周 月 │ 前复权 不复权 后复权 ┃ 水平线 趋势线 圆 标记 选择 测幅 吸附开 撤销
                                  ↑ 常驻，用竖线分隔
```

| 操作 | 做法 |
|---|---|
| 画 | 选一个工具 → 拖动，或**两次点击**（见下） |
| 选中 | 「选择」模式：点线选中一条；**在图上拖动 = 框选多条** |
| **框选删除** | 框选后按 **Delete**（或点「删除选中的 N 条」）一次删掉 |
| **框选放大** | **不选任何工具**时在图上拖动 → 把视图缩放到这段横向范围 |
| **点某根 K 线** | 不选工具时点一下 → **钉住**那根的 开/高/低/收/量 + 涨跌幅；再点同一根取消 |
| **测幅** | 「测幅」→ 拖出两点（或点两下）→ 显示**涨跌幅 / 价差 / 相隔根数** |
| **Esc** | 从画线/测幅 → **回到「选择」模式**；已在选择模式 → 取消选中 |
| 删除 | 选中后按 **Delete**；**Esc** 取消选中 |
| **撤销** | **Ctrl+Z**，或点「撤销」——不必"先去点选择、再找到那条线、再删" |
| 写说明 | 选中后下方出现输入框，可写**标签**与**为什么画在这里** |
| **改颜色** | 选中图形后，**图上的浮动调色板**贴在**鼠标点选的位置**出现 |
| 趋势线延伸 | 选中趋势线后出现 **线段 / 射线 / 直线**，点了立刻生效（**默认射线**） |
| **吸附开关** | 按钮显示**当前实际生效**状态（**吸附开 / 吸附关**）；按住 Ctrl 会取反并同步改变显示 |

> 四种模式的指针行为互不冲突：
> **画线**（选了画线工具）· **框选多选**（选择）· **测幅**（测幅）· **框选放大**（不选任何工具）。
>
> 框选放大只按**横向范围**缩放——价格轴是按可见 K 线自动定的，纵向不参与（如实说明，不假装）。
>
> **测幅不落库**：它是一次"看一眼"的操作，不是研究产物（要留下判断就用画线 + 说明）。
> 相隔用**根数**而不是日历天数——K 线根数才是交易语义，日历天会把周末算进去。

### 测幅是"看一眼"的操作

1. **只在「测幅」工具激活时显示**——切到别的工具或按 Esc 就消失（不会一直留在图上）
2. **不落库**——要留下判断就用画线 + 写说明
3. **两点按日期存、按日期解析**：缩放/平移后仍指向同一天

> ⚠️ 第 3 条是修掉的一个真 bug：测幅点一开始存的是**窗口下标**，
> 于是缩放/平移后同一个下标指向**另一根 K 线**，测幅位置会漂。
> 这与画线"x 必须锚日期"是同一个道理——**同一个类别的错误我在同一个功能里犯了两次**。
>
> 修完后的实测（同一组点，换不同窗口起点）：
>
> | 窗口起点 | 解析出的相对下标 | 指向的日期 |
> |---|---|---|
> | 0 | a=100 b=160 | 2026-03-13 → 2026-06-11 |
> | 50 | a=50 b=110 | 2026-03-13 → 2026-06-11 |
> | 150 | a=-50 b=10 | 2026-03-13 → 2026-06-11 |
>
> 相对下标随窗口变、**日期不变**——位置就不会漂。

### 怎么点中一条画线（命中规则）

| 类型 | 判定 |
|---|---|
| 水平线 | 到那条水平线的垂直距离（容差 6） |
| 标记 | 到该点的距离 |
| 趋势线 | 到**延伸后实际可见的那条线**的距离——射线的延长段、直线的两端延长段**都能点中**（曾经只能点原来那一小段） |
| 圆 | 到**圆周**的距离；圆心附近也可选中（便于选中小圆）。**圆内部空白不抢点击**——免得一个圈把里面其它东西的点击都吃掉 |

> **画圆时不会标出"决定半径的那个点"**：实测用户会把它误当成"自己不小心画的一个点"。
> 圆本身已经把半径表达清楚了；只有**选中时**才点出圆心，便于理解它锚定在哪。

> 圆的屏幕半径可能很小：30 元的价格差在 389 元跨度上只有约 18px。
> 所以选不中时优先**框选**它——框选按包围盒判定，不依赖精确点中。

### 两种画法：拖动，或两次点击

两点型工具（趋势线 / 圆）**两种画法都支持**：

| 画法 | 操作 |
|---|---|
| 拖动 | 按下并拖动 → 松手完成 |
| **两次点击** | 点一下定第一点（松手后仍是预览、随鼠标动）→ 再点一下定第二点 |

判定标准是**屏幕位移**：超过阈值算拖动，否则算"点了一下"。

> 这顺带解决了"圆拖不出来就变成一个点"：以前松手即落地，位移≈0 时半径≈0、什么也看不见；
> 现在小位移会**转入两次点击模式**，等第二下定半径。

### 调色板为什么必须"独占指针"

调色板画在图表 SVG 里，而图表容器的 `onPointerDown` / `onClick` 会接管指针。所以：

1. 调色板的 `pointerdown` 与 `click` 都 `stopPropagation()` —— 否则点色块等于**又在画下一条线**，
   或在选择模式下被容器的命中判定**顺手取消选中**（调色板随即消失，看起来像"点了没反应"）
2. 容器在调色板矩形内**既不开始画线、也不做选中判定**

> 实测证据：数据里那条水平线与圆的 `color` 已经是 `blue` —— **说明保存本来就成功了**，
> 坏的只是交互反馈（点完选中被取消、调色板消失）。
> 所以这类问题要看**数据有没有变**，而不是只看界面有没有动。

### 吸附：四个价位都能吸

吸附目标是最近 K 线的 **开 / 高 / 低 / 收** 四个价位里最近的一个。
（早期只做了高/低/收三个，表现为"一根 K 线只能吸 3 个点"。）

关掉吸附时**仍然对齐到那根 K 线的时间轴**，但价格用鼠标位置——
所以"半路价位"也能画，而锚点始终带得到日期。

### 画之前就知道会得到什么（这是手感的关键）

- **按下之前**：鼠标移动时显示一条**幽灵提示**——水平线给出整条淡色虚线（价格已吸附），
  其它工具给出"会吸附到哪根 K 线"的点。所以**不用先点下去就能看出落点**
- **按下之后**：预览线随鼠标实时变化，端点带圆点
- 线宽：普通 0.8 / 预览 1.2 / 选中 1.5
- 光标变十字，且拖动时不会误选中页面文字

### 四种工具

| 工具 | 锚点 | 说明 |
|---|---|---|
| 水平线 | 1 | 价格位（颈线/支撑） |
| 趋势线 | 2 | **默认射线**；可切成线段/直线 |
| 圆 | 2 | **圆心 + 圆上一点**；半径 = 两点的**价格差**（不是连线长度），图上标出 `±价格差` |
| 标记 | 1 | 标记某一天（财报日/事件日） |

### 颜色：存「色名」而不是色值

存进文件的是 `"color": "red"`，**不是 `#ff0000`**。原因：色值一旦写死，**明暗主题切换后就可能看不清**
（浅色主题下合适的深蓝，放到深色主题上几乎不可见）。存色名由客户端映射到主题 token，
同一条线在明暗主题下都能看清。

> 主题只提供品牌色与四种状态色，**没有紫色 token**。紫色用 `color-mix()` 由两个 token 派生（红 + 蓝）——
> 仍然跟随主题，也没有硬编码色值。非法色名（含 `#ff0000` 这类色值）会被**明确拒绝**并说明原因。

> ⚠️ **一个根因造成三个症状（值得记住）**：`resolveDrawings` 在构造"可绘制形状"时
> **只带了 label/reason，丢掉了 `color` 与 `ext`**。存库完全正确，是渲染前被丢的，于是：
>
> | 症状 | 真实原因 |
> |---|---|
> | 改颜色不变色 | `color` 被丢 → 永远用默认色 |
> | 趋势线预览是射线、画出来却是线段 | `ext` 被丢 → 回落成线段（预览走的是草稿，恰好带着 ext） |
> | 选中后切换延伸方式"没反应" | 存进去了，渲染时又被丢 |
>
> 现在把所有会影响渲染的字段集中在一个 `carry(d)` 里透传，并有一条测试**断言透传**
> （新增字段时要同时加，否则会静默失效）。

> ⚠️ **两个踩过的坑，都值得记住**：
> 1. **预览线不跟随** —— 图表画水平线读的是 `s.price`，而草稿只带了 `points`，
>    于是 `yP(undefined)` = NaN、线根本不可见（幽灵线能显示，只是因为那条路径恰好设了 `price`）。
>    现在两边都兼容 `price` 与 `points[0].price`，且价格无效就不画（不画 NaN 线）。
> 2. **Ctrl+Z 不生效** —— `onPointerDown` 里的 `e.preventDefault()` 会**阻止浏览器把焦点交给容器**，
>    而键盘事件只在容器有焦点时才到达。所以画完线按 Ctrl+Z 没反应；
>    而 Delete 能用，是因为那是在**选择模式**下点的图（那条路径没有 `preventDefault`）。
>    现在按下时会**显式聚焦**容器。

**延伸怎么算**：两点确定直线后按模式取参数区间（线段 `t∈[0,1]`、射线 `t∈[0,∞)`、直线 `t∈(-∞,∞)`），
再对画布矩形做 slab 裁剪。锚点投影可能落在画布外（平移走了），**不裁的话会出现坐标极端的线**。
这个函数是纯的，有测试覆盖水平/竖直/斜线/完全在画布外等情形。

**吸附是必须的**：手画的线永远对不准 K 线高低点。所以锚点会先吸附到最近的 K 线，
再把价格吸附到那根的**高 / 低 / 收**三者中最近的一个——这样画出来的线是能对得上的价位。

**画线模式下接管指针，不画时不拦截**：没选工具时保持原有的逐根十字读数，
选了工具才进入画线状态（十字光标 + 禁止选中文本，避免拖动时选中文字）。

**选中后能写「为什么画在这里」**：不做这一步，手画的线就只是条线；
而画线的价值在于**记下一个判断**。AI 画的线能带 `reason`，人画的也应该能带。

> 比例尺只有一处计算（`computePriceScale`），图表与交互层共用——
> 两边各算一份的话，叠加公式线时范围会不一致，画线就会偏。

> ⚠️ **一条踩过的坑（值得记住）**：`ChartStage` 的解构列表曾漏掉 `windowStart`，
> 而函数体里用了它 → **一按鼠标就抛 `ReferenceError`，草稿建不起来**，
> 表现是"线画不上"（选中却正常，因为那条路径不碰它）。
> 纯函数测试抓不到这种错——只有 React 事件路径才会执行到。
> 所以加了一条**通用守门测试**：**调用点传入的每个 prop，组件必须解构**。
> 这条测试当场就抓出了这个 bug。

### 坐标锚点：这个功能最关键的决定

**x 锚定「日期」，y 锚定「价格」**，并且每条线记录**画它时的复权模式**。三个都会导致"画得对、显示歪"：

| 坑 | 后果 | 做法 |
|---|---|---|
| 用 **K 线序号**存 x | 换根数 / 新数据到来 → 线跑到别处，而"看起来仍然正常" | 存日期，绘制时再解析成当前窗口下标 |
| 用价格存 y 但**不记复权模式** | 前复权基准在除权后整体平移 → 线与蜡烛错位 | 记录 `adjust`；不一致时画成**虚线 + 明确提示** |
| 直接把鼠标坐标当 SVG 坐标 | 容器不是 900px 宽时线会偏 | 用共享几何 `CHART_GEO` 换算（与缩放同一份） |

**复权不一致时为什么"照画但标注"**：不画会让人以为线丢了，画成实线会让人以为它还对得上——
两种都比"画虚线 + 说明"更糟。

### 存储

```
数据根目录/drawings/<标的>.json     每标的一个文件，便于备份、手工查看、被 AI 读写
```

不放在 localStorage：画线是**研究产物**（"我在这个位置做了一个判断"），不该只活在某个浏览器里。
每条线可带 `reason`（为什么画在这里）——画线的价值在于**表达判断**，不只是看图方便。

**数据不合法就报错，不静默修正**：日期格式、价格类型、复权模式都严格校验；
文件损坏或个别条目不合法会**如实报告**并保留合法条目，而不是当成"没有画线"。

### 数据落库

```bash
# 通过 AI 工具（推荐）：collect_history(["SH600519","IDX000300"], count=500)
# 或直接命令行
python backend/collectors/collector.py fetch-many SH600519 SZ300750 IDX000300 --count 500

python backend/collectors/collector.py version SH600519 IDX300      # 数据版本指纹
```

> **数据根目录：Node 与 Python 两侧解析规则完全同构**（2026-10-28 修复）。
> 顺序：`DSH_STOCK_LAB_DATA` → `DSH_STOCK_LAB_HOME/data`（这两档是显式指定，**直接采用**）→
> `$DSH_HOME/stock-lab/data` → `<包根>/data`（后两档按**"真的有 K 线文件"**挑选）。
> 所以裸跑 `collector.py status` 与插件运行期看到的是**同一个库**，不需要额外加环境变量。
> （此前 Python 侧少一档"包内 `data/`"，命令行会指向空库、与运行期分叉；现已对齐，且有跨语言契约测试守着。）

存储布局：

```
data/                                  ← 数据根目录（Node/Python 两侧同构解析，见下）
├── meta.db                         SQLite：采集元信息（行数/区间/来源/时间/后端）
└── bars/<symbol>/1d_qfq.csv.gz     K线（按标的与周期分区）
```

- **格式可替换**：环境装了 `pyarrow` 或 `fastparquet` 时自动改用 Parquet，调用方无感
- **增量合并**：重复采集自动按 `time` 去重合并，不会重复占空间
- **可复现**：`data_version()` 生成数据指纹，Research Note 会**自动记录**

### Node 直读本地库（无需 Python 子进程）

`src/datasource/local.js` 用 Node 原生能力读本地库：`node:zlib` 解 `csv.gz`、`node:sqlite` 读 `meta.db`。因此 K 线的日常读取**不启动 Python 子进程**。

> ⚠️ **读写两方必须指向同一目录**。本地库的写入方是 Python、读取方是 Node，若各自按不同顺序回退，就会出现「写进了 A、却去 B 读」——数据明明在却显示"本地无数据"。
> 现在的做法是**两份实现、同一套规则**：`src/data-root.js` 的 `resolveDataRoot()` 与 `backend/storage/storage.py` 的 `_home()`
> 逐步对齐（环境变量优先级、包内兜底、"有数据"的判据全部一致），并由跨语言契约测试**真的让 Python 跑一次 `_home()`、与 Node 的 `resolveDataRoot()` 逐字比对**；运行期 quant-bridge 还会把 Node 解析结果作为 `DSH_STOCK_LAB_DATA` 传给子进程，作为第二道保险。
> ⚠️ **"有数据"的判据是"有真实 K 线文件"**（`bars/<symbol>/` 下的 `*.csv.gz`/`*.parquet`），**不是** "`meta.db` 或 `bars/` 目录存在"——空库曾经把真库顶掉，见「已知的本地数据层坑」。

`local.js` 按**列名**取值（不依赖列顺序），列顺序变化不会破坏读取；有对应测试。

### getKline 的来源路由

| source | 行为 |
|---|---|
| `auto`（默认） | 本地库覆盖足够且新鲜（最后一根 ≤7 天）→ 用本地；否则走实时源 |
| `local` | 只用本地库，不足或缺失则报错（研究场景，可复现） |
| `live` | 强制实时源 |

每根 bar 都带 `source` 字段（`local` / `tencent` / `sina`）；`getKlineInfo()` 额外返回 `provenance`：

```json
"provenance": {
  "dataSource": "本地历史库", "sourceKey": "local",
  "upstreamSource": "tencent", "localRows": 501,
  "localRange": "2024-09-25 ~ 2026-10-23",
  "dataVersion": "caa00cc1be59e3cf", "reproducible": true
}
```

**相对强弱**因此从 80 根扩到 **500 根（两年）**，并同时报告个股与基准两侧的溯源。

### 数据版本自动写入研究笔记

`save_research_note` 不填 `dataVersion` 时会自动处理：

- 本地库**有**该标的 → 填入实际数据指纹（可精确复现）
- 本地库**没有** → 如实写「live（实时接口数据，未落库，无法精确复现）」

**不假装可复现**——这比填一个看起来专业的假指纹重要。

### Event Study

五种内置条件：`volume_spike`（放量）、`breakout`（突破N日新高）、`drawdown`（回撤）、`ma_cross`（均线上穿）、`big_move`（单日大涨大跌）。

输出：样本量、平均/中位超额收益、标准差、**t 统计量**、胜率、显著性判定，以及**强制附带的因果免责**。

两种入口：工作台「量化验证」tab（可视化，结果可一键存为笔记）；AI 工具 `run_event_study`（对话中调用）。

真实运行示例（茅台，放量后 5 日）：

```
52 个样本 | 平均超额 +0.59% | 中位 -0.81% | t=0.96 | 胜率 44.2% | 不显著
```

这是一个**诚实**的结果：均值被极端值拉高而中位数为负，说明"放量后上涨"在这个样本里没有统计支撑。

> 设计取向：宁可报"不显著"，也不把噪音包装成规律。所以 UI 把**样本量与 t 值放在最显眼的位置**，而不是只展示一个好看的收益数字。

### Python 解释器配置

插件按以下顺序查找 Python：`DSH_STOCK_LAB_PYTHON` → 包内 `.python-path` 文件 → `DSH_PYTHON` → DSH 自带运行时（`$DSH_HOME` 或 `~/.dsh` 下的 `dsh-runtimes/.../python.exe`）→ PATH 上的 `python`。

> ⚠️ DSH 宿主进程里 `DSH_HOME` 未必设置、`python` 也不在 PATH，所以**实际生效的是 `~/.dsh` 回退**。诊断：`GET /stock-lab/quant/python` 会返回探测过程与最终选择。

## Research Notebook

研究记录是本项目区别于普通行情插件的核心。数据落在 `$DSH_HOME/stock-lab/research/`：

```
research/
├── index.db                      SQLite 索引（可查询、可统计）

```

一条 note 包含：观察（客观事实）/ 假设（明确标注是假设）/ 证据 / 反证（必须尽力找）/ 预测 / 置信度 / 复盘日 / 数据版本 / 基准 / 来源 / 状态。

AI Tools：

| 工具 | 用途 |
|---|---|
| `save_research_note` | 把一次分析固化成可复查记录 |
| `list_research_notes` | 按股票/状态筛选；`dueOnly` 列出到期未复盘的 |
| `review_research_note` | 记录复盘结论（correct / partially / wrong / void） |
| `research_notebook_stats` | 历史判断的结论分布（并提醒样本少时不可当胜率） |

复盘的目的是**修正认知**，不是证明自己猜对了：记录哪部分对、哪部分错、遗漏了什么、因果理解是否有误。

## 已知的本地数据层坑（实测）

- **空库会顶掉真库**（2026-10-28 修复）：
  旧判据是「`meta.db` 或 `bars/` 目录存在 → 视为有数据」。但 `collector.py status` 这类**只读命令**
  会顺手 `ensure_dirs()` + 建 `meta.db`（schema 建好、0 行），于是 `$DSH_HOME/stock-lab/data` 这个
  **空目录**被当成"有数据"，把包内 `data/`（真有 5 个标的）整个顶掉。
  症状：`status` 报"尚无落库数据"、界面本地 K 线为空、**画线也全部消失**（`drawings/` 跟着根目录走）。
  修法三步：① "有数据"改判「`bars/<symbol>/` 下至少有一个 `*.csv.gz` / `*.parquet`」；
  ② 只读路径（`bars_path` / `load_bars` / `list_bars_meta` / `data_version`）**不再创建任何目录**；
  ③ Python `_home()` 补上「包内 `data/`」兜底，与 Node **完全同构**。
  回归测试：`tests/local-storage.test.mjs`（空库 / 真库 / 缓存 / 跨语言同构 4 项）+
  `backend/tests/test_storage.py`（解析优先级 / 空库不算数据 / 只读不建目录 / 0 字节库 8 项）。
- **解析结果有缓存，但只在"环境变量+10 秒"内有效**：`local.js` 每次读盘都会调 `resolveDataRoot()`，
  不能每次都扫目录；缓存键包含三个环境变量，所以改 env 立刻失效，新采集的数据最多 10 秒后被看到。
  测试里要立即生效就调 `__resetDataRootCache()`（只给测试用）。

## 已知的数据源坑（实测记录）

- 腾讯 `qt.gtimg.cn` 字段是**按位置**的（`~` 分隔），完整映射写在 `src/datasource/tencent.js` 注释里。关键位置：**f36 成交量(手)、f37 成交额(万元)、f38 换手率(%)、f39 PE、f46 PB、f47/f48 涨跌停价**。早期版本误把 f36 当成交额、f37 当换手率，导致成交额差 10 倍、换手率变成 76 万这种荒唐值。
- 腾讯**指数**的涨跌幅在 f38（个股在 f32），且指数涨跌停字段返回 `-1`，须归一为 `null`。
- 东财 `push2 stock/get` 的 `f43`（价格）、`f162`（PE）、`f167`（PB）是**放大 100 倍**的整数
- 东财财务接口字段是 `REPORTDATE`（无下划线），不是 `REPORT_DATE`
- 东财 `push2 stock/get` 的 `f62`（主力净流入）不可用，须用 `fflow/kline`
- 腾讯分时点格式为 `"0930 1311.84 1049 137612016.00"`（时间 价 累计量 累计额），是字符串数组
- 腾讯 smartbox 搜索的 `data.stock` 是**数组的数组**：`["sh","600519","贵州茅台","","GP-A"]`
- 成交量 z-score 在历史标准差为 0 时（一字板/长期停牌）会算出无穷大，用 ±99 封顶而非返回 null——否则"极端异常"反而被静默吞掉

## DSH 插件机制坑（实测）

- `ctx.set()` 需要插件声明 `export const provide`，否则启动报 `cannot set property ... without provide`。不需跨插件共享时，直接用闭包持有实例。
- **`ctx.tools` / `ctx.skills` 只有在 `inject` 里声明后才存在。** 只写 `inject: ['webServer']` 时 `apply` 里 `ctx.tools === undefined`，AI Tools 会静默注册失败——界面正常但 AI 完全用不了。现已加 `tools`、`skills` 并配回归测试。
- 验证注册是否生效（不要只看 UI）：
  - `cordis_inspect_query` → host `Tool.listTools`，应能看到全部 **30 个** `stock_*` / 其它本插件工具（少一个都说明注册装配出了问题）
  - 会话可用 skill 目录里应出现 `stock-lab`
  - 直接调一次 `stock_quote` 或 `stock_research_snapshot`
- 改 Host 代码后必须 remove + install 重装才生效（`lib`/`src` 的 Host 半边不在 HMR 范围）；Client 半边（`src/client.js`）由 HMR 推送，刷新页面即可。
